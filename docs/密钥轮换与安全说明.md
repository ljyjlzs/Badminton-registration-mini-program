# 密钥轮换与安全说明

> 本文档记录密钥清单、轮换触发条件、轮换步骤与验证清单，供开发与运维执行。
> 含历史泄露处理决策（见文末附录）。

## 1. 密钥清单

| 密钥 | 用途 | 存放位置 | 负责人 | 轮换时间 |
|------|------|----------|--------|----------|
| AI_API_KEY（小米 Mimo） | AI 聊天/文案/解析/视觉 | 云开发控制台 → 云函数环境变量；本地 `cloudfunctions/*/cloudbaserc.json`（不入库） | 管理员 | 建议每 90 天；泄露时立即 |
| 微信 appsecret | 小程序登录 code2session | 微信公众平台后台；服务端配置（不入库） | 管理员 | 建议每 180 天；泄露时立即 |
| 云 API 密钥（腾讯云 API 密钥） | 云开发 CLI / 腾讯云 API | 腾讯云控制台 → 访问管理；本地 `~/.tencentcloud/` 或环境变量（不入库） | 管理员 | 建议每 90 天；人员变动时 |
| TCB envId | 云开发环境标识 | `cloudbaserc.example.json` 占位；真实值在本地 `cloudbaserc.json`（不入库）；小程序 `miniprogram/config/env.js` | 管理员 | 一般不轮换；环境迁移时更换 |
| AMAP_KEY（高德） | 逆地理编码 | 云开发控制台 → 云函数环境变量 | 管理员 | 建议每 180 天 |

## 2. 轮换触发条件

| 触发条件 | 需轮换的密钥 | 紧急程度 |
|----------|--------------|----------|
| 密钥进入 git 历史（任何提交/PR） | 对应密钥全部立即轮换 | 立即 |
| 明文密钥写入文档/报告并可能外传 | 对应密钥 | 24 小时内 |
| 人员离职/权限变更 | 云 API 密钥、AI_API_KEY、微信 appsecret | 3 个工作日内 |
| 供应商侧泄露公告（如 Mimo） | AI_API_KEY | 按公告时限 |
| 例行周期（90/180 天） | 按上表周期 | 计划内 |
| 疑似滥用（用量异常、陌生调用） | 对应密钥 + 排查日志 | 立即 |

## 3. 轮换步骤

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 在对应控制台生成新密钥 | 先生成再失效旧钥；必要时灰度并行 |
| 2 | 更新云开发控制台 → 云函数 → 环境变量 | 至少 `ai-chat`、`ai-history`、`generate-copy`、`parse-activity`、`photo-ai-note`、`rules-qa`、`invite`、`recommend-time` 等所有 AI 函数 |
| 3 | 更新本地 `cloudfunctions/*/cloudbaserc.json` | 仅本地，永不入库 |
| 4 | 重新部署受影响云函数 | 上传并部署：云端安装依赖 |
| 5 | 停用/删除旧密钥 | 确认新钥生效后执行 |
| 6 | 记录轮换时间 | 更新本文档「密钥清单」表的轮换时间列 |

## 4. 验证清单

| 验证项 | 方法 | 通过标准 |
|--------|------|----------|
| AI 聊天可用 | 小程序发一条消息 | 正常回复，无 AI_NOT_ENABLED |
| AI 文案生成 | 组织者生成活动文案 | 返回 announcement/share/invite |
| 聊天建活动解析 | 发送「明天 8 点宝安双打」 | 返回草稿 |
| AI 问答（规则） | 询问规则问题 | 有 answer 或 fallback |
| usage 成本日志 | 云函数日志搜 `[ai-usage]` | 有 usage 字段输出 |
| 登录 | 小程序登录 | code2session 成功 |
| 无明文入库 | `git ls-files \| grep -i cloudbaserc.json` | 零命中（example 除外） |

### A.2 历史处理决策（C-6 书面结论）

# 运行时告警接入说明

> 第 10 章完整性复核维度 ④。当前项目运行时告警覆盖率为 0，本文给出接入建议。

## 1. 现状

| 项 | 状态 | 证据 |
|---|---|---|
| Sentry / Bugsnag / Fundebug 等 APM | 零命中 | 全仓 miniprogram + cloudfunctions |
| 钉钉 / 企业微信 / 飞书告警 webhook | 零命中 | 同上 |
| 云函数错误统一上报 | 无 | 各函数 `catch (err) { return { success:false, message: err.message } }` 静默吞掉，不落库、不告警 |
| 前端错误监听 | 无 `wx.onError` / `App.onError` 全局钩子 | app.js 只做云初始化 |
| 日志 | 仅 console.log（云函数侧） | 无集中采集 |

结论：线上故障（AI 超时、数据库写失败、权限拒绝）只能靠用户反馈或控制台日志人工翻查。

## 2. 接入建议（按优先级）

### P0 — 云函数错误出口统一上报

在 `cloudfunctions/_shared/logger.js` 增加 `reportError(fnName, err, ctx)`：

1. 优先接微信云开发**云函数日志 + 告警**（控制台可配错误率阈值），零代码改动即可起步。
2. 需要更细粒度时，接 Sentry（`@sentry/node`）或腾讯云可观测（CLS + 告警策略）。
3. 各云函数 `catch` 分支调用 `reportError`，不要只 `return { message: err.message }`。

### P1 — 关键业务写路径埋点

高价值、低频、失败即资损/体验事故的路径单独告警：

- `create-activity` / `delete-activity`（数据增删）
- `join-activity` / `cancel-registration` / `handle-cancel-request`（报名状态机）
- `court-submit-score`（比分 + 积分结算）
- `ai-chat` / `parse-activity` 等 AI 调用（额度烧尽、超时）

### P2 — 小程序前端

- `App.onError` / `wx.onError` 捕获 JS 异常上报。
- `request.js` 封装里对 `success:false` + 5xx 集中上报。

### P3 — 成本/额度告警

- AI 调用已打 `[ai-usage]` 日志（`_shared/ai.js`），可据此配额度水位告警。

## 3. 最小可用方案（一天内可落地）

1. 微信云开发控制台 → 云函数 → 日志告警，开启「错误次数阈值」。
2. 新建钉钉/企微机器人 webhook，`_shared/logger.js` 里对 `error` 级日志 POST 一条文本。
3. 不引入 SDK，保持零依赖原则（当前 67 个云函数只依赖 `wx-server-sdk`）。

## 4. 结论

运行时告警 = **未接入**。建议按 P0→P3 分层补，优先统一云函数错误出口。

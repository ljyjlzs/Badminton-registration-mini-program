# 03-分组赛程排名模块（算法已对齐 Java 源码）

> 覆盖：`start-grouping`(preview+apply)、`submit-score`、`get-rankings`、`match-live-score`、`match-reminders`。
> 本文算法逐行对齐 `GroupingPlanServiceImpl` / `RankingServiceImpl` / `ScoreServiceImpl` / `MatchReminderServiceImpl`。
> **关键修正**：分组按 `activity.type` 分四种；排名按**场均积分**（非胜场）；比分积分 = `myScore-opponentScore`。

## 3.1 分组算法（buildPlan，按 type 分支）

### 公共
- 校验：有报名；`registrations.size() >= minPlayers`；fixed-doubles 需偶数人。
- 排序打分 `mixedScore = level*10 + rating/100`（rating 缺省按 `1000+(level-5)*80`）。
- 队伍名展示：优先自定义 `name`，否则成员昵称用 `/` 拼接（如 `张三/李四`）。
- 提交后活动 `status='grouping'`（不是 playing）；match `status='pending'`，`round='group'`，`court` 标签 `场地A/B/...` 或自定义。

### A. singles（单打）
- 每人一队（`teams = [[u1],[u2],...]`）。
- 赛程 = **全循环**：所有 (i<j) 两两成赛；按 `teamTotalLevel`（队内成员 level 之和）**升序**排 `roundOrder`。
- reasons：`"单打：{昵称}单独成队"`。

### B. doubles（双打轮换）
- 圆桌轮转：所有人尽量两两搭档至少一次；每轮配对，奇数人时 1 人轮空(dummy)。
- 比赛 = 每轮两两组队；若某轮奇数对，余 1 对进入 `leftovers` 后续与无冲突对补足。
- reasons：`"轮转组合：A+B（第n轮）"`。
- `repeatNotice`：若出现重复搭档组合，提示“轮转双打中部分搭档组合会重复出现：…排名按场均积分计算”，需前端确认。

### C. fixed-doubles（双打固搭）
1. 按 `mixedScore` 降序排序。
2. 先绑定 `partnerId` 搭档（`used` 标记），reasons：`"固搭绑定：A与B互为搭档"`。
3. 剩余用**双指针**：左（高分）与右（低分）配对 → `"按水平最高配最低：A+B"`。
4. 赛程 = 全循环，按 `teamTotalLevel` 升序排 `roundOrder`。

### D. court-doubles（按场地双打）
- 每场地 `capacity≥4`，取该场地 `assignedUserIds` 子集，各自调用 B（轮转双打）。
- 跨场地 `roundOrder` 连续递增；`court` 标场地标签。

### AI 分组解释（generateAiExplanation）
- 仅当 AI 可用：system=`"你是羽毛球活动分组讲解员…只输出 JSON：{\"summary\":\"150字内\"}，只解释分组逻辑，不评价实力、不编造胜负人数"`；user=确定性 reasons + 队伍摘要。
- 结果 `summary≤150` 字符；失败/不可用返回 `null`（前端不展示）。

## 3.2 start-grouping（落库 apply）
- `preview` 不落库；`apply` 调 buildPlan → 写 `teams`(members JSON) → 写 `matches`(team1Id/team2Id 由 pairKey 映射) → `activity.status='grouping'`。
- court-doubles 额外校验 `CourtAssignService.checkReady`。

## 3.3 submit-score（提交比分）
**入参** `{ matchId, team1Score, team2Score }`，提交人须为参赛成员或代报人/组织者。
**校验**：0 ≤ s ≤ 30；**不允许平局（a==b 拒绝）**；非 finished。**提交即生效，无需对手确认**（Java 不强制 21 分制，仅规则文案如此描述）。
**步骤**
1. 写 `scores`：对 team1 每位成员 `scoreChange = team1Score - team2Score`，team2 每位 `scoreChange = team2Score - team1Score`；`source='group'`。
2. 更新 `matches`：`status='finished'`, `team1Score/team2Score`（胜者由比分推导，matches 表无 `winnerTeamId` 字段）。
3. **更新水平分**：调 04.1（写 `rating_changes` + 更新 `users.rating`）。
4. 清理该场 `match_live_states`。
5. 返回更新后的 match。

## 3.4 get-rankings（排名，对齐 RankingServiceImpl）
- 取活动所有 `scores` + `rating_changes` + `registrations`。
- **个人排名**：`totalScore = Σ scoreChange`；`playedMatches = 该用户参与的比赛数（同场只算一次）`；`avgScore = totalScore/playedMatches`。
  - **排序：`avgScore` 降序 → `totalScore` 降序 → 昵称升序**。
  - rating 缺省 `1000+(level-5)*80`；`ratingDelta` 来自 `rating_changes`。
- **队伍排名**（type=team/all）：成员 `scoreChange` 去重累加 `totalScore`；排序 `totalScore` 降序 → 队名升序。
- 返回 `{ individualRankings:[{rank,userId,nickname,avatar,level,rating,ratingDelta,groupScore,totalScore,avgScore,matchCount}], teamRankings:[...] }`。

## 3.5 match-reminders（实时提醒，对齐 MatchReminderServiceImpl）
- 轮询间隔 `pollIntervalSeconds` 默认 **10s**；仅 `grouping/playing` 状态返回 `pollInterval`，否则 0。
- 取“与当前用户相关”的比赛（本人所在队 / 代报队）：
  - 相关比赛 `playing` → 若现场比分为**关键分**(`isKeyScore`) 类型 `key_score`，否则 `match_started`。
  - 相关比赛 `pending` 且前面同范围比赛全 finished → `next_match`（下一场）；否则 `waiting_previous`（准备中）。
  - 组织者无队伍时 fallback 展示最早 playing/pending。
- `isKeyScore(a,b)`：`(max>=29 && diff<=1) || (a==b && a>=20) || (max>=20 && diff==1)`。
- 全局视角 `globalCurrent/globalNext`：最早 `playing` / 最早 `pending`；`playing` 带 30 分钟内有效的现场比分快照（`match_live_states`，过期不带）。

## 3.6 match-live-score（现场比分）
- 写 `match_live_states`：`0 ≤ score ≤ 30`；`finished` 比赛拒绝；提交人权限同 3.3。
- 终局 `submit-score` 后由服务清理。前端每 10s 轮询 `match-reminders` 展示。

# 10-验收标准与测试计划

> 终态：badminton-app（sync-java-backend）功能与体验 == badminton-app-java（P0–P7，单一赛制）。

## 10.1 验收口径（门禁）
1. **分支/架构**：仅 `sync-java-backend` 分支改动；无 Java 文件；无合并 Java 历史；challenge 系列已移除。
2. **核心闭环**：创建活动 → 报名（含固定搭档/候补）→ 分组（含理由）→ 提交比分（含校验）→ 排名 → 战报 → 徽章/水平分，全链路可用。
3. **AI 能力**：ai-chat / parse-activity / generate-copy / rules-qa / recommend-time / invite 在 `AI_API_KEY` 配置下可用；缺密钥时全部降级不报错。
4. **相册**：上传(安全校验)/点赞/精选(≤9)/评论(限长限条)/AI 小计可用。
5. **语音天气提醒**：语音填分(腾讯ASR) + 天气 + 实时提醒/现场比分可用；ASR 失败降级手动。
6. **按场地双打**：场地配置/开始/赛程/比分/排行可用。
7. **前端**：页面迁移完成，调用层统一 `callFunction`；原有云函数未被破坏。

## 10.2 测试计划
### 单元/逻辑（云函数内）
- **分组算法**：按 `type` 四种（singles 全循环 / doubles 圆桌轮转 / fixed-doubles 固搭+高配低 / court-doubles 按场地轮转）；teamTotalLevel 升序；reasons 非空。
- **比分校验**：0–30 且**不允许平局**（a==b 拒绝）；21 分制不强制校验（仅规则文案）；提交即生效、无需对手确认。court-submit-score（云函数层）额外校验 `match.court` 归属该场地，服务端 `submitScore` 不重算归属。
- **Elo(rating)**：K=32+分差权重(1.0–1.3)，高 rating 胜低 rating 涨幅小、负则降幅小；断言 delta 对称性；默认 rating=1000+(level-5)*80。
- **徽章**：5 类（mvp/best_partner/streak_king/hard_worker/biggest_win）按活动触发正确。
- **配额**：语音每小时≤10、每场≤30、每活动≤200；评论单照≤200、每人≤20。
- **精选**：featured 上限 9。

### 集成（真机/模拟器）
- 用真实微信云环境跑通 10.1.2 全链路。
- ASR 用真实录音文件验证识别→比分；断网/错误 key 验证降级。
- 天气接口用真实 location 验证（open-meteo 与 amap 两种 provider）。
- 相册上传用真实图片触发 `imgSecCheck`（含一张违规图验证拦截）。

### 回归（不破坏现有）
- 原 login / activity-detail / 分享 等云函数与页面仍正常。
- `init-rules` 仍可用，新增默认规则不冲突。

- **ASR 厂商确认**：若腾讯 ASR 不可用，需替换 7.2 的识别实现，接口契约不变。
- **天气 provider**：默认 open-meteo 免费；amap 需 key。

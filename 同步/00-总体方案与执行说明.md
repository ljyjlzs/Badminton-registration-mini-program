# 00-总体方案与执行说明

> 本文档是 badminton-app-java（Spring Boot，P0–P7 全量功能）同步到 badminton-app（微信小程序 + 微信云函数）的总体方案与执行说明，供开发实施。
> 生成日期：2026-08-28。分支：`sync-java-backend`（已基于 `origin/codex/ui-refresh` 创建并推送）。

## 1. 背景与目标
把 badminton-app-java 的全部功能（含前端页面 + 后端能力），用目标仓库 badminton-app **既有的微信云函数架构**重新实现；最终使用体验与 badminton-app-java 一致（单一赛制、无挑战赛）。

## 2. 已确认决策（锁死，勿偏离）
1. **不破坏目标架构**；新分支 `sync-java-backend` 继承 `codex/ui-refresh` 历史；**不引入任何 Java 文件**，**不合并 badminton-app-java 的 Java 提交历史**。
2. **移除 challenge 系列**：删除云函数 `create-challenge-match`、`start-challenge`、`start-final`、`get-challenge-data` 与前端 `challenge` 页面；保持单一赛制，逻辑与 Java 项目一致。
3. ASR 优先**腾讯 ASR**；不可行再议替代方案。
4. 云数据库（文档型）用「**多次查询 + 内存关联**」实现关联逻辑（不使用联表）。

## 3. 分支与工作流（已执行）
- 仓库：`D:\project\badminton-app`（remote `origin` = `ljyjlzs/Badminton-registration-mini-program`）。
- 已执行：`git fetch` → `git checkout -b sync-java-backend origin/codex/ui-refresh` → `git push -u origin sync-java-backend`。当前分支即 `sync-java-backend`。
- 云函数环境变量（**不入库**，在云开发控制台配置）：`AI_API_KEY`(→`ai.api-key`)、`AI_BASE_URL`(→`ai.api-url`)、`AI_MODEL`(默认 `mimo-v2.6-pro`，→`ai.model`)、`TENCENT_ASR_SECRET_ID`、`TENCENT_ASR_SECRET_KEY`、`AMAP_KEY`(→`weather.amap.key`)、`WEATHER_PROVIDER`(默认 `amap`，→`weather.provider`)。

## 4. 目标架构约定（开发必须遵守）
- 每个云函数：`cloudfunctions/<name>/index.js`，导出 `exports.main = async (event, context) => {...}`。
- 入参约定：`event = { action: string, payload: object }`；返回 `{ success: boolean, data: any, message: string }`。
- 鉴权：在云函数内 `const cloud = require('wx-server-sdk'); cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV }); const wxContext = cloud.getWXContext(); const openid = wxContext.OPENID;` 用 `openid` 关联 `users._openid`。
- 数据库：`const db = cloud.database();` 集合见 `01-数据模型对齐.md`。
- 前端调用：在 `miniprogram/utils/request.js` 新建 `callFunction(name, action, data)`，统一封装 `wx.cloud.callFunction`，并对返回做 `{success,data,message}` 解包。
- **不要破坏现有云函数**（login/create-activity/...），在其内扩展逻辑；新增云函数按 `02`–`08` 规格新增目录。
- 文件存储：照片/语音改用**微信云存储**（`cloud.uploadFile` / `wx.cloud.uploadFile`），上传前 `security.imgSecCheck`。

## 7. 移植总原则（贯穿所有模块）
- **只读 MySQL → 多次查询云数据库 + 内存关联**：Java 用 MyBatis-Plus 联表，云函数改用多次 `db.collection().where().get()` 后在 JS 里组装。
- **状态机保持一致**：报名 `apply_status ∈ {active, waiting}`；`cancel_status ∈ {pending, approved, rejected}`；比赛 `status ∈ {pending, playing, finished}`；活动 `status`（registering/grouping/playing/finished 等，见 02）。
- **降级原则一致**：AI/天气/ASR 不可用时返回确定性结果或隐藏入口，绝不抛错阻塞主流程。
- **权限一致**：组织者（活动创建者）专属操作需校验 `activity.creatorOpenid === openid`；有效报名/候补可看可评相册等。

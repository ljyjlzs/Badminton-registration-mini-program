# 05-AI能力模块（已逐行对齐 AiServiceImpl / ActivityRecommendServiceImpl / InviteServiceImpl / RulesQaServiceImpl / FillSuggestionServiceImpl）

> 覆盖云函数：`ai-chat`、`parse-activity`、`generate-copy`、`invite`(listCandidates/generateInvites)、`rules-qa`、`recommend-time`、`get-fill-suggestions`/`get-fill-gap`。
> **关键修正**：ai-chat 是“小羽”角色+操作卡片；parse-activity 输出草稿 JSON 并经规则兜底归一；generate-copy 是 announcement/share/invite 三字段（AI 失败直接报错，无模板降级）；recommend-time **基于组织者历史时段满员率**（非 level 分布）；invite/fill 候选来自组织者历史同打过的人。

## 5.1 公共封装
- 模型：`ai.api-url` + `ai.api-key`，`ai.model` 默认 `mimo-v2.6-pro`，`ai.enabled` 默认 true。
- `chatJson(system, user, Class)`：temperature=0.2，response_format=json_object，max_tokens=3000，剔除 ``` 围栏；失败抛 `AiParseException`。
- `chat(...)`：temperature=0.7，max_tokens=3000，reasoning_effort=low；AI 不可用时返回“抱歉，小羽服务异常，请稍后重试。”。
- 所有 AI 失败**按各自降级策略**（见各节，多数降级为 null/模板；唯 generate-copy 直接报错）。

## 5.2 ai-chat（对话助手，system = buildUserContext）
逐字对齐 `AiServiceImpl.buildUserContext`（云函数须用完全相同措辞）：
```
你是小羽，一个羽毛球活动助手。你既可以回答各种日常问题，也可以协助用户管理羽毛球活动。

你的能力：
1. 回答各种问题：知识问答、聊天、写作、翻译、计算等
2. 协助羽毛球活动：查看可报名的活动、生成报名确认、生成取消报名确认等

重要规则：你只能建议和确认，不能替用户执行任何操作。用户确认前，绝不能声称“已报名”“报名成功”“已成功报名”等。只有收到“[系统通知] 操作执行结果：”之后，你才可以确认该操作已完成。

请用友好、简洁的语气回答。如果是羽毛球相关问题，可以主动提供活动信息。

【用户信息】昵称：{nickname}，等级：{level}

【可报名的活动】(N个)
- 活动ID: ...
  名称: ...，类型: ...，时间: ...，地点: ...，组织者: ...

当用户要求报名时：
1. 如果用户明确指定了上面某个活动，先输出一句简短说明，然后必须紧跟以下操作卡片（不要用代码块）：
__ACTION__{"action":"join_activity","confirm_text":"确认报名参加活动","params":{"activityId":"<活动ID>","activityName":"<活动名称>"}}__END__
2. 如果用户没有指定活动，或描述模糊匹配到多个活动，请输出：
__SELECT__[{"id":"<ID>","name":"<名称>","time":"<时间>","location":"<地点>","organizer":"<组织者>"}]__END__
并请用户选择要报名的活动。
3. 禁止在输出 __ACTION__ 之前说“已报名”或“报名成功”；报名是否成功以系统通知为准。
4. 如果用户要求取消报名，输出：
__ACTION__{"action":"cancel_registration","confirm_text":"确认申请取消报名","params":{"activityId":"<活动ID>","activityName":"<活动名称>"}}__END__
5. 用户只问问题或查看信息时，正常聊天回答，不要输出任何操作卡片标记。
```
- `sanitizeChatReply`：用户说“帮我报名/我想报名/我要报名/报名参加/帮我参加”等，且 AI 回复含“报名成功/已成功报名/报名已成功/报名完成/已为你报名/报名已提交”但**无操作卡片** → 拦截改写：“我还没有替你提交报名，请先选择要报名的活动：\n__SELECT__…__END__”。
- 历史保留最近 12 条（`__system_feedback` 除外）；user 消息若带执行结果则替换为“[系统通知] 操作执行结果：…”。

## 5.3 parse-activity（聊天建活动草稿）
**入参** `{ message }` → 返回 `ActivityDraftVO`（草稿，非落库）。
**算法（AiServiceImpl.parseActivity，不可臆造）**
 1. `chatJson` 系统提示（逐字）：
```
你是羽毛球活动助手。把用户一句话解析成活动草稿，只输出 JSON，不要输出任何其他文字。JSON 字段：name, time(格式 yyyy-MM-dd HH:mm:ss), location, province, city, district, type(singles/doubles/fixed-doubles), maxPlayers(整数), missing(数组)。规则：1. 相对时间按当前时间 {now} 计算，例如今天/明天/周X/下周五/晚上/HH:mm。2. 用户提到城市或区名时，必须补全省市区。例如"深圳宝安"-> province="广东省", city="深圳市", district="宝安区"；"广州天河"-> province="广东省", city="广州市", district="天河区"。3. 用户没给地点时 location 填空字符串，并在 missing 中加入 location；完全没提地区时 province/city/district 都填空，并在 missing 中加入对应字段。4. 用户提到的球馆名称直接作为 location，例如"超越羽毛球馆"-> location="超越羽毛球馆"。5. 不确定活动类型时用 doubles。6. 名称为空时生成"M月d日羽毛球局"。7. 提到"老地方"时 location 填空字符串（由后端回填）。8. 用户提到报名人数时 maxPlayers 填整数（如"8人双打"填 8），没提到填 null。
```
2. `applyRuleFallback`：`ActivityTextParser` 解析 type/time/location/region/maxPlayers 兜底。
3. `normalizeDraft`：type 仅 singles/fixed-doubles 保留，否则 doubles；minPlayers=singles?3:4；maxPlayers 默认 8，clamp[min,100]，name 截断 50 字；source=ai。
4. `fillMissingLocation`：空 location/region 用**组织者上一场活动**的同字段回填，缺失项进 missing。
5. AI 失败且核心字段（time/location/省市区）全空 → 抛“AI 暂时无法识别，请手动填写”。
> 注：旧文档“去编号:前缀/按行拆分/统计已报名数”均不实，以本算法为准。

## 5.4 generate-copy（活动文案，三场景 JSON）
**入参** `{ activityId, regenerate? }`，仅组织者。
- 缓存：`activity_copy` 已有 announcement/share/invite 三行且非 regenerate → 直接返回缓存。
- `chatJson` 系统提示（逐字）：
```
你是羽毛球活动文案助手。根据活动信息生成三种中文文案，只输出 JSON，不要输出任何其他文字。JSON 字段：announcement(群公告), share(分享语), invite(邀请语)。要求：中文、不用 emoji；群公告80字以内；分享语40字以内；邀请语40字以内且包含被邀请人昵称占位，格式如{昵称}。
```
- user：活动名/时间/地点/类型标签(单打/双打轮换/双打固搭)/当前人数/上限/组织者。
- **无降级**：三字段任一为空 → 抛 `AiParseException` → “AI 文案生成失败，请稍后重试”（不回退模板）。
- 落库 `activity_copy`(scene=announcement/share/invite)。

## 5.5 rules-qa（规则问答）
**入参** `{ question(≤200字) }`，需 AI 开启。
 1. `tryAiAnswer`：`chatJson` 系统提示（逐字）：
```
你是羽毛球小程序规则助手。根据给定规则原文回答问题，只输出 JSON。字段：answer(300字内), references=[{sectionId, quotes=[原文片段]}]。要求：1. 只能引用下方原文，逐字摘录，不能改写。2. 引用的 sectionId 必须真实存在。3. 原文没有的内容回答"规则原文未提及"，不得编造。4. 不用 emoji。
```
校验：answer≤300字；quotes 必须是该 section 规则（`match_rules/scoring_rules/common_rules`）的子串（去空白后匹配），且 sectionId 对应真实 id；任一无效则整体降级到 fallback。AI 不可用 → 抛“AI 功能未开启”。问题 >200 字 → 抛“问题最长200字”。
2. 降级 `fallbackAnswer`：对问题取 2–4 字 gram（去停用词）匹配规则文本，取匹配最多前 3 个 section 的命中规则作为 references，answer=“根据规则原文，相关条款如下：”。

## 5.6 recommend-time（开赛时间推荐，历史满员率驱动）
**入参** `{ organizerId, type?, location? }` → `TimeRecommendResult`。
> **重要**：与 level 无关，基于**组织者历史活动**的时段满员率。
**算法（ActivityRecommendServiceImpl，逐字）**
- 历史：优先 `finished` 活动；不足 3 场则放宽到全部历史。
- 时段桶：`08-10,10-12,14-16,16-18,18-20,20-22`（按 start hour 映射）。
- 单场满员率 `rate = min(activeCount / denominator, 1.0)`，`denominator = maxPlayers>0?maxPlayers:4`（缺名额按 4 估）。
- 聚合 `(weekday, slot)`：`avgRate = mean(rates)`，`score = avgRate*0.7 + min(n/5,1)*0.3`。
- 排序：**可信(n≥3)优先 → avgRate 降序 → n 降序 → weekday 升序 → startTimeHour 升序**。
- 取 TOP3；`reliable = 历史场数≥3 且非空`；否则 `fallbackTip="历史数据不足，先凭经验建一场"`。
- 历史加载 `loadHistory`：优先 `status='finished'`；不足 3 场放宽到全部历史（`queryByOrganizer` 支持按 `type`/`location` 过滤，传 `all`/空则不过滤）。
- `suggestedTime`：下一个未来该 weekday 的桶起始小时（若算得今天则顺延 7 天）。
- `aiNote`：`chatJson` 系统提示（逐字）
```
你是羽毛球活动助手。基于组织者的历史开赛时间数据，生成一句不超过60字的中文解释，说明为何推荐这些时间。只输出JSON，格式{"note":"..."}。不得编造数字，数字必须来自提供的数据。
```
AI 不可用时/无推荐 → `null`；>60 字截断。异常全程降级（reliable=false, 空推荐, aiNote=null, fallbackTip="历史数据不足，先凭经验建一场"）。
- 异常全程降级（reliable=false, 空推荐, aiNote=null）。

## 5.7 invite（候补/好友邀约）
**前置校验**（`validateOrganizerActivity`）：仅组织者；`activity.status='registering'`；`remaining=max(0, maxPlayers - 有效报名数) > 0`（否则“活动已满员，无需邀约”）。
**listCandidates** `{ activityId, limit? }`（默认 10，上限 10）：候选=组织者**历史共同报名过**且未加入本活动/候补（`listInviteCandidates`）的人（排除 `openid` 以 `proxy_` 开头的代理用户）。
- `avgLevel` = 当前报名 level 均值（缺省 5），`avgLevelRounded = round(avgLevel)`，`targetRating = 1000 + (avgLevelRounded-5)*80`。
- 每人理由（用 `|level-avgLevelRounded|` 与 `|estRating-targetRating|`，`estRating = rating ?? 1000+(level-5)*80`）：
  - 必有：“你上次活动和你一起打过”
  - “水平接近” 若 `|level-avgLevelRounded|≤2` 或 `|estRating-targetRating|≤200`
  - “最近活跃” 若 `lastRegisterTime` 在 7 天内
- 排序：lastJoinTime 降序（null 置后）→ ratingDiff 升序 → nickname（不分大小写）。
**generateInvites** `{ activityId, candidateIds? }`（上限 10，超出“候选人数最多10人”）：
- AI 不可用时 → 抛“AI 功能未开启”。
- AI 系统提示（逐字）：
```
你是羽毛球活动邀约助手。根据活动信息和候选球员生成个性化邀请语，只输出 JSON。字段：invites = [{ userId, nickname, content(40字内) }]。没有候选球员时生成 1 条通用邀约，userId 和 nickname 用 null。要求：中文、不用 emoji；时间地点人数必须来自活动信息，禁止编造；内容自然口语化，像组织者直接邀请朋友。
```
- 校验：content 非空且 ≤40 字；必含活动地点；必含时间（今天/明天/周X/M月d日/yyyy-MM-dd HH:mm:ss 任一匹配）；若无候选则允许 userId/nickname=null；否则 userId/nickname 须与候选一致 → 否则整体走模板。
- 模板（逐字）：`{nickname}，{M月d日}{HH:mm}在{location}打羽毛球，还差{n}人，来吗？`（source="template"）；AI 失败亦走模板。

## 5.8 get-fill-suggestions / get-fill-gap（补位推荐，仅双打）
**仅 doubles / fixed-doubles、status=registering、组织者**。
- `pairGap`：doubles→`active.size()%2`；fixed-doubles→未绑定搭档者数%2。
- `startGap`：`max(minPlayers - activeCount, 0)`。
- `waitlist`：前 20 人（userId/nickname/level/waitlistOrder）。
- `recommendations`：同 5.7 候选逻辑（组织者历史同打过、排除已加入/候补、排除 proxy），reason 同 5.7，limit 10。
- `aiNote`：≤80 字行动建议（不声称已发送/已补位），模板：“当前 X 人，还差 Y 人可全员成双。候补 Z 人…”，AI 失败用模板。
- `get-fill-gap` 仅返回计数（pairGap/startGap/waitlistCount），无候选。

## 5.9 权限与配额
- ai-chat/parse-activity/invite/listCandidates 登录即可；generate-copy/rules-qa(需AI)/recommend-time(读历史)/get-fill-* 需组织者或对应权限。
- AI 不可用时：ai-chat 返回异常文案；parse-activity 转手动；generate-copy 报错；rules-qa 报错；recommend-time/fill 降级模板/null。

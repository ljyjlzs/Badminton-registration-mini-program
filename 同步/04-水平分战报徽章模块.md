# 04-水平分战报徽章模块（算法已对齐 Java 源码）

> 覆盖：`rating`（比分后更新，见 03.3 第3步触发）、`badge`(generateForActivity)、`report`(buildStatsMap)、`user-summary`。
> 对齐 `RatingServiceImpl` / `BadgeServiceImpl` / `ReportStatsServiceImpl`。
> **关键修正**：水平分 K=32 且带分差权重；徽章是 5 类按活动生成，不是“首胜/高手”文案。

## 4.1 rating（动态水平分，对齐 RatingServiceImpl.applyMatch）
**常量**
```
K = 32
默认 rating（无记录者） = 1000 + (level - 5) * 80      // level 缺省 5 → 1000
队伍平均 rating 缺成员默认 = 1200
```
**算法（每场 finished 且比分非空）**
1. 取 team1/team2 成员；队伍平均 rating `rA=mean(成员rating)`、`rB=mean(成员rating)`（缺则按上面默认）。
2. `expected1 = 1 / (1 + 10^((rB - rA)/400))`；`expected2 = 1 - expected1`。
3. `diff = |team1Score - team2Score|`；`weight = 1 + min(diff,15)/15 * 0.3`（范围 1.0–1.3）。
4. `delta1 = team1 胜 ? winnerDelta(expected1, weight) : -winnerDelta(expected2, weight)`
   - `winnerDelta(e,w) = max(round(32 * (1 - e) * w), 1)`（至少 ±1）
   - `delta2 = -delta1`
5. team1 每位成员 `rating += delta1`，team2 每位 `rating += delta2`；写 `rating_changes{ratingBefore, ratingAfter, delta}` 并回写 `users.rating`。
6. **改比分重算**：先撤销旧 `rating_changes`（用 `before = current - oldDelta` 还原），再按新比分计算（保证幂等）。

## 4.2 badge（徽章，对齐 BadgeServiceImpl.generateForActivity）
**5 类（badgeCode / 标题 / 条件，按活动生成，清旧再写新）**
- `mvp` ／ MVP ／ 胜率最高（`winRate` 最高且 `matchCount>=2`）
- `best_partner` ／ 最佳搭档 ／ 固定搭档共同获胜最多（`partnerStat.winCount>=2` 且等于最大值，双方各一枚）
- `streak_king` ／ 连胜王 ／ 最大连续获胜（`maxStreak>=2`）
- `hard_worker` ／ 劳模 ／ 参赛场次最多（`matchCount>=3`）
- `biggest_win` ／ 大比分胜利 ／ 最大分差获胜场次的所有胜方成员
**统计口径（ReportStatsServiceImpl.computeStats）**：基于 `matches(status='finished')` 累加每人 `winCount/matchCount/totalScore(=Σ(myScore-oppScore))/winRate/avgScore/maxStreak`；`partnerWins` 仅统计双人胜场的搭档组合。

## 4.3 report（活动战报，对齐 buildStatsMap）
字段：`activityName, time, location, type, playerCount, matchCount` +
- `top3`：按 `avgScore` 降序→`totalScore` 降序→昵称升序，取前 3（含 rank/nickname/score/avgScore/winCount/matchCount）
- `mvp`(nickname, winRate, avgScore)
- `bestPartner`(names, winCount)
- `streakKing`(nickname, streak)
- `hardWorker`(nickname, matchCount)
- `biggestWin`(nickname, diff, score)
- `closestMatch`(score)
战报写入 `activity_reports` 集合（实体 `ActivityReport`：status `generating→finished/failed`，含 title/content/statsJson/errorMessage）；当活动所有比赛 `finished`、活动状态变 `finished` 时由事件触发 `generateAsync` 异步生成（先生成徽章再生成战报）；`get-report` 返回 `none/generating/finished` 与正文，`regenerate` 需组织者且活动已 finished。AI 可用时用战报写手提示（title≤50 字、content 150–250 字、只输出 JSON）生成，异常回退模板文案。

## 4.4 user-summary（个人总览）
返回 `UserSummaryVO`（用于个人主页与候补推荐）。`get-summary` 入参 `periodType`∈{`year`,`season`}（season 需 `quarter`∈1–4），年份默认当年、季度默认当前季度；只统计 `status='finished'` 且时间在周期内的活动。
- 顶层：`periodType, periodKey, periodStart, periodEnd, stats(StatsVO), badges(BadgeSummaryVO[]), aiContent, source(ai|template), statsVersion, generatedAt`。
- `stats`(StatsVO)：`activityCount, matchCount, winCount, loseCount, winRate(%), totalScore(净胜分合计), avgScore(场均净胜分), maxStreak, bestPartner, bestPartnerWinCount, biggestWin("a:b"), biggestWinOpponent, ratingStart, ratingEnd, ratingDelta, mvpCount, badgeCount, favoriteLocation, topLocations(TopLocationVO[])`。
- `badges[]`(BadgeSummaryVO)：`badgeCode, title, description, earnedAt`（取前 20）。
- `topLocations[]`(TopLocationVO)：`name, count`（按次数前 3）。
- 缓存：`user_summary` 表按 `(userId, periodType, periodKey)` 存 `aiContent`+`statsVersion`，指纹(比赛/徽章/积分变更)变化或 `force=true` 才重算（AI 或模板兜底，文案≤120 字）。

## 4.5 权限与缓存
- 徽章/战报（4.1–4.3）仅组织者或有效报名（含代报）可见；由 `badge`/`report` 云函数触发生成并缓存。
- `get-summary`（4.4）返回调用者本人总览，后端按 `(userId, periodType, periodKey)` 缓存 `aiContent`（`statsVersion` 指纹变化或 `force` 才重算）。

# 08-按场地双打（court-doubles）模块（已逐行对齐 CourtAssignServiceImpl / ActivityCourt / CourtAssignment / Match.court）

> 覆盖云函数：`court-config`、`court-add`、`court-delete`、`court-save-label`、`court-list`、`court-assign`（autoAssign）、`court-move`、`court-ready`、`court-matches`（分组）、`court-submit-score`、`court-rank`。
> 对齐 `CourtAssignServiceImpl`。
> **关键修正**：`court` 在 `matches` 里是**字符串标签（如"场地A"）**；`activity_courts` **无 status 字段**（只有 courtNo/label/capacity）；`config` 入参是单个 `playersPerCourt`（不是场地列表）；`autoAssign` 是 **round-robin（idx % 场次数）**；match 生成不在本服务内，由分组服务按每场 assignedUserIds 调用 03.1B。

## 8.1 配置（court-config / court-add / court-delete / court-save-label）
- 仅 `activity.type='court-doubles'` 可配置；否则 `BusinessException("该活动类型不支持场地划分")`。
- 仅在 `status='registering'` 时可配置/编辑。
- `config(activityId, playersPerCourt)`：`playersPerCourt ≥ 4`（否则"每场人数至少4人"）。
  - 若无场地 → **自动建 1 个场地**（courtNo=1，`label="场地A"`，capacity=playersPerCourt）。
  - 若已有场地 → 同步改所有场地 capacity（新值不可小于当前人数最多的场地；否则报错）。
  - 落库：`activity.courtCount`、`activity.playersPerCourt`、`activity.maxPlayers = courtCount * playersPerCourt`。
- `addCourt`：新增 1 个场地（courtNo=max+1，`label="场地X"`，capacity=playersPerCourt），更新 courtCount 与 maxPlayers。
- `deleteCourt(courtNo)`：删场地及 `court_assignments`，更新 courtCount 与 maxPlayers。
- `saveLayout`：**仅更新场地 label**（不改 capacity）。
- 场地标签规则（`courtLabel`）：index≤26 → `场地` + (A~Z)；否则 `场地` + index。

## 8.2 查看（court-list = getLayout）
- 组织者或参与者（assertParticipant）可看。
- 返回 `courts[]`：每项 `{ courtId, courtNo, label, capacity, members[] }`；`members` = `court_assignments` 对应该场地的报名：`{ userId, registrationId, nickname, level(缺省5) }`。
- 返回 `unassigned[]`：有效报名（applyStatus='active'）中**未分配**到任何场地者：`{ userId, nickname, level }`。

## 8.3 分配（court-assign = autoAssign / court-move）
- `autoAssign(activityId)`：仅组织者 + registering。取有效报名中**未分配**者，按列表顺序 **round-robin `idx % courtCount`** 写入 `court_assignments`（字段：activityId/courtId/userId/registrationId；`roundOrder` 字段存在但分配阶段不填）。不按 rating/水平。
- `move(targetUserId, toCourtId)`：把某用户移到目标场地（无记录则新建）；随后 `validateCourtCapacity`：任一场地人数 > playersPerCourt → `BusinessException("有场地人数超过每场人数上限")`。
- 分配仅写入 `court_assignments`，**不直接生成 matches**。

## 8.4 分组（court-matches，云函数编排，不在 CourtAssignService 内）
- `court-start`（或独立 `court-matches`）对**每个场地**取 `court_assignments` 中该场地的 `assignedUserIds`，调用 **03.1B 轮转双打**（`buildRotatingDoublesPlan`）生成该场 `matches`：
  - `match.court = 该场地 label`（字符串，如"场地A"）；`roundOrder` 在该场地内递增。
  - court-doubles 的报名 `teamId` 为空，**固定搭档不跨场绑定**。
- 全局 `globalCurrent/Next` 由 03.5 提醒服务按最早 `playing`/`pending` 给出（无"场地 status"概念）。

## 8.5 提交比分（court-submit-score）
- 同 **03.3 的 submit-score**：0–30、不允许平局、非 finished、提交即生效。
- 额外校验：`match.court` 归属目标场地（云函数需传正确 matchId，服务端不重算归属，与前端点对单侧一致即可）。
- 更新水平分（04.1）、排名（03.4）与现场比分清理，逻辑与普通过场一致。

## 8.6 排行（court-rank）
- 同 03.4 `get-rankings`：活动级个人/队伍排名（场均积分排序），不按场地拆分。

## 8.7 开工校验（court-ready = checkReady）
返回 `ReadyCheckVO{ ready, messages[], totalAssigned, unassignedCount }`，`ready=true` 需**全部满足**（否则 messages 含原因）：
- 无重复用户：同一 userId 出现在多个场地 → "存在重复分配到多个场地的用户（需一人一场）"。
- 每场人数：若 `1 ≤ n < 4`（MIN_PLAYERS_PER_COURT）→ "X场地仅 n 人，至少需 4 人（或删除该场地）"；若 `n > playersPerCourt` → "X场地有 n 人，超过每场人数上限 m 人"。
- 无未分配：有有效报名未分配 → "有 N 人未分配场地"。

## 8.8 补位推荐（get-fill-suggestions，见 05.8）
- 仅 `doubles`/`fixed-doubles` 支持（`court-doubles` 用 8.3 手动分配即可）；详见 05.8。

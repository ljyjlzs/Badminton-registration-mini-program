## 三、功能需求

### 3.1 紧急修复（P0，必须立即修复）

#### 3.1.1 代报功能逻辑错误

**需求描述**：
用户报名后，再帮其他人代报同一活动时，系统错误提示"您已报名此活动"，无法完成代报。

**用户故事**：
> 作为一个已报名的用户，我希望帮朋友代报同一活动，这样朋友不需要自己操作也能参加活动。

**当前行为**：
1. 用户A报名活动X
2. 用户A帮用户B代报活动X
3. 系统提示"您已报名此活动" ❌

**期望行为**：
1. 用户A报名活动X
2. 用户A帮用户B代报活动X
3. 代报成功 ✅
4. 用户A帮用户C代报活动X
5. 代报成功 ✅
6. 用户A帮用户B再次代报活动X
7. 系统提示"该姓名已在活动中报名" ✅

**验收标准**：
- [ ] 已报名用户可以帮他人代报同一活动
- [ ] 代报时检查被代报人姓名是否重复，而非检查代报人
- [ ] 同一姓名不能重复代报
- [ ] 代报记录正确显示代报人信息

**优先级**：P0（紧急）  
**影响范围**：`join-activity` 云函数、活动详情页

### 3.2 P0 功能（核心流程）

#### 3.2.1 候补报名

**需求描述**：
当活动人数已满时，用户可以加入候补队列；有人取消报名时，候补用户按排队顺序自动补位。

**用户故事**：
> 作为用户，当活动已满时，我希望加入候补队列，这样有人取消时我能自动补位参加活动。

**功能流程**：

```
用户报名 → 活动已满？
                ↓ 是
        自动进入候补队列
                ↓
        显示候补位置（第X位）
                ↓
        有人取消报名
                ↓
        自动补位（候补→正式报名）
                ↓
        通知用户已补位成功
```

**业务规则**：
1. 活动人数达到 `maxPlayers` 时，新报名用户自动进入候补
2. 候补用户按报名顺序排队（`waitlistOrder` 从1开始）
3. 有人取消报名时，按排队顺序自动补位
4. 候补用户可以取消候补
5. 候补用户不占用活动名额

**界面要求**：
- 活动详情页显示"活动已满，加入候补"按钮
- 候补用户显示"您在候补第X位"
- 活动详情页显示候补人数

**验收标准**：
- [ ] 活动满员后可以继续报名（进入候补）
- [ ] 候补用户按报名顺序排队
- [ ] 有人取消时，候补用户自动补位
- [ ] 候补用户可以取消候补
- [ ] 界面正确显示候补状态和位置

**优先级**：P0  
**影响范围**：`join-activity`、`cancel-registration` 云函数、活动详情页

#### 3.2.2 冲突检测

**需求描述**：
用户报名时，系统自动检测是否与同时间段其他已报名活动冲突，并提示用户确认。

**用户故事**：
> 作为用户，当我报名新活动时，系统提醒我同一时间段有其他活动，避免时间冲突。

**功能流程**：

```
用户点击报名
    ↓
系统查询用户所有已报名活动
    ↓
筛选出与当前活动时间冲突的活动（前后2小时内）
    ↓
有冲突？
    ↓ 是
显示冲突活动列表，提示用户确认
    ↓ 用户确认
继续报名
```

**业务规则**：
1. 检测范围：当前活动时间前后2小时内的其他活动
2. 只检测 `applyStatus='active'` 的报名记录
3. 有冲突时提示用户，用户可选择继续报名
4. 不阻止报名，仅提醒

**界面要求**：
- 弹窗显示冲突活动列表（活动名称、时间、地点）
- 提供"继续报名"和"取消"按钮

**验收标准**：
- [ ] 报名时自动检测时间冲突
- [ ] 正确显示冲突活动信息
- [ ] 用户可以确认继续报名
- [ ] 不阻止报名，仅提醒

**优先级**：P0  
**影响范围**：`join-activity` 云函数、活动详情页

---

#### 3.2.3 比赛排序

**需求描述**：
组织者可以手动调整比赛顺序，保存后生效。

**用户故事**：
> 作为组织者，我希望调整比赛顺序，这样可以根据实际情况灵活安排比赛。

**功能流程**：

```
组织者进入赛程页面
    ↓
显示比赛列表（按当前顺序）
    ↓
长按拖动调整顺序
    ↓
点击"保存"按钮
    ↓
顺序保存成功
```

**业务规则**：
1. 只有活动组织者可以调整比赛顺序
2. 比赛顺序存储在 `matches` 集合的 `roundOrder` 字段
3. 保存后立即生效
4. 比赛列表按 `roundOrder` 排序显示

**界面要求**：
- 赛程页面显示比赛列表
- 长按可拖动调整顺序
- 右上角"保存"按钮
- 拖动时有视觉反馈

**验收标准**：
- [ ] 组织者可以拖动调整比赛顺序
- [ ] 保存后顺序生效
- [ ] 非组织者无法调整顺序
- [ ] 比赛列表按新顺序显示

**优先级**：P0  
**影响范围**：`update-match-order` 云函数、赛程页面

### 3.3 P1 功能（用户体验）

#### 3.3.1 比分修改

**需求描述**：
对局双方和组织者可以修改已提交的比分。

**用户故事**：
> 作为对局者或组织者，当比分提交错误时，我可以修改已提交的比分。

**业务规则**：
1. 只有对局双方（`team1` 和 `team2` 的成员）和活动组织者可以修改比分
2. 比分范围：0-30
3. 不允许平局
4. 修改后重新计算积分
5. 修改后更新 `scores` 和 `rating_changes` 集合

**界面要求**：
- 比赛详情页面显示"修改比分"按钮（仅对局双方和组织者可见）
- 点击后弹出比分输入框
- 确认后修改比分

**验收标准**：
- [ ] 对局双方可以修改比分
- [ ] 组织者可以修改比分
- [ ] 其他用户无法修改比分
- [ ] 比分修改后积分重新计算
- [ ] 比分范围校验（0-30，不允许平局）

**优先级**：P1  
**影响范围**：`submit-score` 云函数、比赛详情页

#### 3.3.2 徽章系统

**需求描述**：
活动结束后自动生成徽章，用户可以查看自己的徽章列表。

**用户故事**：
> 作为用户，活动结束后我可以获得徽章（如MVP、最佳搭档等），并在我个人中心查看所有徽章。

**徽章类型**：

| 徽章代码 | 名称 | 图标 | 获得条件 |
|----------|------|------|----------|
| `mvp` | MVP | 🏆 | 本次比赛得分最高 |
| `best_partner` | 最佳搭档 | 🤝 | 配合最默契的搭档 |
| `streak_king` | 连胜王 | 🔥 | 连续获胜最多 |
| `hard_worker` | 努力奖 | 💪 | 参与比赛最多 |
| `biggest_win` | 最大胜分 | 🎯 | 单场胜分最多 |

**业务规则**：
1. 活动状态变为 `finished` 时自动生成徽章
2. 每个徽章每个活动最多授予一个用户
3. 徽章存储在 `badges` 集合
4. 用户可以在个人中心查看所有徽章
5. 活动详情页显示本次活动获得的徽章

**界面要求**：
- 个人中心页面显示徽章列表
- 活动详情页显示本次活动徽章
- 徽章显示图标、名称、描述

**验收标准**：
- [ ] 活动结束时自动生成徽章
- [ ] 徽章生成规则正确
- [ ] 个人中心正确显示徽章列表
- [ ] 活动详情页正确显示徽章

**优先级**：P1  
**影响范围**：`update-activity-status` 云函数、`badges` 集合、个人中心页面、活动详情页

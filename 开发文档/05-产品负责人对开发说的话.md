## 二、需要开发做的事情

### 2.1 紧急修复（优先级最高）

#### 问题描述

用户报名后，再帮别人代报同一活动时，系统错误提示"您已报名此活动"，无法完成代报。

#### 问题原因

`join-activity` 云函数第43行检查重复报名时，使用 `userId: openid` 检查当前用户，但代报时应该跳过这个检查，改为检查被代报人的姓名是否已存在。

#### 修复方案

1. 代报时（agent=true）跳过当前用户的重复报名检查
2. 改为检查被代报人的姓名是否已存在（通过 nickname 检查）
3. 参考源项目 `RegistrationServiceImpl.java` 第87-89行

#### 修复代码

```javascript
// 在 doJoin 函数中，第42行之前添加判断
if (payload.agent) {
  // 代报逻辑：跳过当前用户的重复报名检查，改为检查被代报人的姓名
  const existingByName = await db.collection('registrations')
    .where({
      activityId: payload.activityId,
      nickname: payload.nickname.trim(),
      cancelStatus: _.neq('approved')
    })
    .get();
  
  if (existingByName.data.length > 0) {
    return { success: false, message: '该姓名已在活动中报名' };
  }
  
  // 生成临时 userId
  const agentUserId = 'agent_' + openid + '_' + Date.now();
  
  // 创建报名记录（后续逻辑保持不变）
  // ...
}
```

#### 测试验证

- [ ] 已报名用户可以帮他人代报同一活动
- [ ] 代报时检查被代报人姓名是否重复，而非检查代报人
- [ ] 同一姓名不能重复代报

## 三、开发注意事项

### 3.1 代码规范

1. **云函数结构**：每个云函数 `index.js`，导出 `exports.main`
2. **入参约定**：`event = { action, payload }`
3. **返回约定**：`{ success, data, message }`
4. **鉴权方式**：`cloud.getWXContext().OPENID`

### 3.2 数据库操作

1. **多次查询 + 内存关联**：云数据库不支持联表，需要多次查询后在内存中关联
2. **索引优化**：为常用查询字段添加索引
3. **批量操作**：减少数据库调用次数

### 3.3 错误处理

1. **统一错误格式**：`{ success: false, message: '错误信息' }`
2. **用户友好提示**：错误信息要让用户看懂
3. **日志记录**：关键操作记录日志

### 3.4 权限控制

1. **组织者权限**：只有活动创建者可以管理活动
2. **报名者权限**：只能操作自己的报名记录
3. **对局方权限**：只能修改自己参与的比赛比分

### 3.5 性能优化

1. **减少云函数调用**：合并相关操作
2. **数据缓存**：缓存不常变化的数据
3. **分页查询**：大数据量使用分页
